title: "Scoped Custom CSS"
description: "Write per-block CSS with the selector keyword, and what the sanitizer strips before output."
---

Every Blicks block has an **Advanced ▸ Custom CSS** field. Rules you write there are scoped to that
one block instance and sanitized before they reach the page.

## The `selector` keyword

Write `selector` where you would normally write the block's class. On output, Blicks replaces it
with that instance's wrapper class (`.bl-<id>`):

```css
selector {
  --ring-size: 12px;
}

selector:hover .bl-icon {
  transform: rotate(8deg);
}
```

Because the replacement is per instance, the same block type styled twice on a page cannot leak
rules into the other copy.

## Where it sits in the CSS pipeline

Blicks emits CSS in three tiers, and custom CSS is the last of them:

1. **Token value → utility class.** Shared and cacheable — one class serves every block using that token.
2. **Custom value → scoped variable + static consumer class.** A CSS custom property carries the literal value; the class consumes it. No inline-style walls.
3. **Custom CSS → block-scoped rule.** What you write here, scoped to the instance.

Each block's base CSS lives in `@layer blicks.base` and initializes its instance variables, so
nested blocks cannot inherit each other's values. Custom CSS is emitted outside that layer, so it
wins against the base without needing `!important`.

## What the sanitizer removes

Before output, custom CSS is truncated to **10,000 characters** and these constructs are stripped:

| Removed | Why |
|---|---|
| `<` | Prevents closing the `<style>` element or injecting markup. |
| `@import` | Blocks pulling in remote stylesheets. |
| `@charset`, `@namespace` | Only valid at the top of a stylesheet; meaningless and risky when scoped. |
| `expression(` | Legacy IE script execution. |
| `javascript:` / `vbscript:` schemes | Script execution through a URL. |
| `data:text/html` | HTML documents smuggled through a data URL. |
| `url(` | Blocks remote asset loading and URL-scheme tricks. |
| `behavior:` / `-moz-binding:` | Legacy binding properties that execute code. |

<Warning>
`url()` is stripped, so background images and `@font-face` sources cannot be set from this field.
Use the block's own background image control, or enqueue a stylesheet from your theme.
</Warning>

## When not to use it

Reach for a token first. Custom CSS is a per-instance escape hatch; anything you would apply more
than once belongs in the design system, where every block can pick it up:

- A repeated color, size, or radius → add a token in **Blicks → Design System**.
- A repeated typographic treatment → edit or add a [type role](/reference/design-system/type-roles).
- A repeated entrance → author a keyframe animation in the **Animation** section.
