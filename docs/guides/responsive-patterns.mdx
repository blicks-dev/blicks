Blicks is **desktop-first**: you style the page at full width, and most of it adapts by itself.
Where a phone needs something different, the block offers a switch for it — **Stack on phones**,
**One column on phones** — instead of a device switcher you have to remember to flip back.

## The three screen sizes

| Screen | Applies at | Media query |
|---|---|---|
| **Desktop** | every width | none — the value everything else overrides |
| **Tablet** | 782px and below | `max-width: 782px` |
| **Phone** | 600px and below | `max-width: 600px` |

782px and 600px are WordPress's own editor breakpoints, so the editor's preview sizes match the
page. Change them under **Blicks ▸ Design System ▸ Screen sizes**. Preview a screen size with the
device menu in the editor's top bar.

A tablet value keeps applying on phones until a phone value overrides it.

## What reflows on its own

Reach for these before setting anything per screen. They respond to the room available, not to the
window:

	<Card title="Grid: Fit to width" icon="layout-grid">
		A Box arranged as a **Grid** with **Columns ▸ Fit to width** fits as many columns as there is room for — never narrower than **Each at least** — and drops columns as the space shrinks.
	</Card>
	<Card title="Side by side wraps" icon="text-wrap">
		A Box arranged **Side by side** puts its children next to each other and wraps them onto a new line when they no longer fit.
	</Card>
	<Card title="Section content width" icon="between-horizontal-start">
		The Section's inner wrapper is capped at your theme's content width and shrinks with the window.
	</Card>
	<Card title="Text sizes" icon="a-large-small">
		A Heading's or Text's size steps down on phones by itself. To choose the phone size, use the **On phones** slider under **Style ▸ Text ▸ Customize**.
	</Card>

## Switches for phones

Where a block's phone layout is usually different, it has a switch. Each one writes a phone value
for you:

| Block | Switch |
|---|---|
| Box, **Side by side** | **Stack on phones** — one under another on small screens |
| Box, **Grid** | **One column on phones** (on by default) |
| Box, **Divider** | **Full width on phones**, for a line shorter than its box |
| Box, **Spacer** | **Half as much on phones**, or **Exact room on phones** |
| Buttons | **Two across on phones** for a grid of buttons |
| Image | **Full width on phones**; phones also load a smaller copy of the file |
| Dialog | **On phones** — keep the card, or make it a bottom sheet or full screen |

Some blocks always change on phones: Steps run **Down**, a List's columns become one, and a
Form's fields take the full row.

The **Loop** sets its columns per screen: switch the editor's preview device and set the count for
each.

## Hiding a block on one screen size

<Frame caption="The ••• tab: Show on, Screen readers and HTML attributes.">
	<img src="/images/inspector/box-4-more.png" alt="The More tab: Show on, Screen readers and HTML attributes" style={{ maxWidth: '280px' }} />
</Frame>

In the **•••** tab, **Show on** has a button for each screen: desktop, tablet and phone. Turn one
off and the block is hidden on the page at that size. With the default screen sizes the ranges
don't overlap — phone is 600px and below, tablet 601–782px, desktop 783px and up — so hiding on
tablet does not also hide on phones.

In the editor a hidden block stays, faded with a dashed outline, so you can still select it.

<Warning>
Hiding still ships the block: it is in the HTML and its images still load. Hide for layout
reasons, not to serve different content to different devices.
</Warning>

## Anything else

When no switch covers it, open **Style ▸ All settings**, choose **Add a setting**, and under
**Smaller screens** pick **Set for tablet** or **Set for phone**. Any setting the block allows can
be given its own value for that screen. The list shows which values are set where, so a phone value
is never hidden behind a mode.

## Checking your work

Preview all three sizes in the editor, then resize a real browser window before you publish. Grids
and side-by-side Boxes reflow at whatever width their content runs out of room, which is usually not
exactly 782px or 600px.
