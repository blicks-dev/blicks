# Blicks Docs — Mintlify

Public-facing Blicks documentation, built with **Mintlify**. It lives inside the plugin repo so
block metadata and the pages describing it change in the same commit.

## Quick commands

From this directory:

```bash
pnpm install        # this directory has its own dependencies (see below)
pnpm generate       # regenerate reference/blocks/*.mdx + docs.json nav
pnpm dev            # generate, then start `mintlify dev`
pnpm check          # generate, then run Mintlify's broken-link check
```

`docs/` carries its own `package.json` and lockfile, and is not part of the plugin's install.
The Mintlify CLI is heavy and nothing else needs it, so the plugin's build, tests and release
jobs never pay for it — the same isolation `tests/integration/` uses for its Composer project.

## How deploy works

Mintlify watches this repo via the **Mintlify GitHub integration**, configured against the
`/docs` path on `main`. Every push rebuilds the site — no CI step required.

Because Mintlify does **not** run build scripts, the generated block reference MDX **must be
committed**. Run `pnpm generate` before committing whenever block source changes (block.json or
per-block readme.md).

## Design system

The palette is the same one the plugin admin ships
(`resources/admin/styles/_shell.scss`) and the same one the logo and favicon draw
with. One system — if the accent moves in the plugin it moves here.

- Sharp corners everywhere (no `border-radius`), except deliberate circles (avatars, status dots).
- Hairline borders + flat surfaces (no shadows).
- Accent `#002bff`, hover/strong `#0022cc`. Dark mode lifts the accent to `#8fb0ff` — the blue this
  system already uses on dark surfaces — rather than switching hue.
- The accent is reserved for the primary CTA, the active nav item, and links in prose. Components
  signal hover with their border, not an accent fill.
- Inter (display + body), mono (code + eyebrows).
- Atomic block grid on the home page.

Both `style.css` and `docs.json`'s `colors` block carry the palette — keep them in step.

### Overriding Mintlify

Mintlify ships Tailwind, so two things bite when adding rules here:

- **Specificity.** Prose styles cells as `.prose :where(td)` — (0,1,0) — which beats a bare
  `th, td`. Page-content overrides are scoped under `#content` / `.prose` so they actually win.
- **Utility classes are not semantic.** Tailwind puts a bare `group` class on every sidebar link
  for its group-hover variants, so `[class*="group"]` matches far more than section headings.
  Prefer real hooks — `.sidebar-group-header`, `#sidebar`, `#table-of-contents`, `#search-bar-entry`
  — and verify against the rendered DOM rather than guessing at class names.

## Adding a new page

1. Create the `.mdx` file with frontmatter:

   ```mdx
   ---
   title: "Page title"
   description: "Short description."
   ---
   ```

2. Reference the path (no extension) in the relevant `navigation.tabs[].groups[].pages` array in
   `docs.json`.

## Block reference workflow

`scripts/generate-block-docs.mjs` reads `../resources/blocks/*/block.json` and
`readme.md`, emits one `.mdx` per block under `reference/blocks/`, and patches the **Blocks** group
in `docs.json` so every page shows in the sidebar.

Run after any block source change:

```bash
pnpm generate
git add reference/blocks docs.json
```
